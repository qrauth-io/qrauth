# Trust Reveal UX

When a user scans a QRAuth-signed QR code, they land on the verification page at `https://qrauth.io/v/:token`. The page does not simply display information — it stages a 3-second animated reveal that communicates trust level before showing any details.

The reveal is implemented entirely in CSS animations and vanilla JS. There is no external animation library.

---

## Success flow

```
1. Shield pop-in      (~400ms)
2. Trust color sweep  (~800ms)   green / amber / red
3. Organization name  (~300ms)
4. Visual fingerprint (~500ms)
5. Fade to detail view
```

### Step-by-step

**1. Shield pop-in**
A shield icon scales in from 0 to 1 with a `cubic-bezier(0.175, 0.885, 0.32, 1.275)` spring. The shield color is neutral (white/dark) until the trust color is determined.

**2. Trust color sweep**
The background performs a radial sweep from the center of the shield outward. The sweep color maps to the trust score:

| Trust score | Color | Meaning |
|---|---|---|
| 80–100 | `#00a76f` (green) | Trusted |
| 50–79 | `#ffab00` (amber) | Caution |
| < 50 | `#ff5630` (red) | Suspicious / fraudulent |

**3. Organization name**
The verified organization name fades in below the shield, accompanied by its trust level badge (`GOVERNMENT`, `BUSINESS`, `INDIVIDUAL`) and KYC status.

**4. Visual fingerprint**
A deterministic SVG of 7 geometric shapes on a 120×120 canvas appears below the organization name. It is derived from a per-scan keyed SHA-256 value, so the pattern differs on every scan. See [Visual fingerprint](#visual-fingerprint).

**5. Detail view**
The overlay fades out and the full verification detail appears: destination URL, location match, content type, and fraud signal summary.

---

## Failure flow

When verification fails (`verified: false` because a signature did not verify, or the final trust score is 20 or below):

1. **Red sweep** — the overlay background escalates from light to deeper red over the 3-second reveal.
2. **Alarm text** — "Fraudulent Code Detected / Do not proceed" scales in once below the "Not Verified" status.
3. **No continue action** — for URL codes, the "Continue" button is replaced by "Do not proceed - this QR code is not verified". JSON API clients still receive `destination_url`.

Users with `prefers-reduced-motion` get the final state without animation.

Revoked, expired and scan-limited codes, and codes with an unsupported `alg_version`, show a simple failure page instead of the reveal. Geo-fence blocks show a location prompt or a block page.

## Visual fingerprint

The fingerprint SVG is generated server-side by `generateVisualFingerprint(seed)` in `packages/api/src/renderers/visual-fingerprint.ts`. The seed is a keyed SHA-256 value over a server-side secret, the token, the scan timestamp and the client IP, so every scan produces a different pattern. The same seed always produces the same SVG.

- 7 shapes on a 120×120 canvas.
- Each shape consumes 4 seed bytes: x position, y position, size, and a byte that selects color and shape type.
- Shape types: circle, rounded rectangle, triangle, diamond. Colors come from an 8-color palette.
- A subtle radial glow sits behind the shapes.

## Ephemeral proof

Every verification page shows an ephemeral proof block: a set of facts generated by the server for this specific scan.

| Field | Value | Source |
|---|---|---|
| Location | e.g. "Athens" | Resolved from the IP address the server saw |
| Device | e.g. "Safari on iOS" | Parsed from User-Agent at scan time |
| Time | e.g. "10 Apr 2026, 14:32" | Server-recorded; not client-supplied |
| Proof ID | 12 hex chars | Keyed SHA-256 over the token, timestamp and client IP; unique per scan, not in the QR payload |

::: info Origin integrity check
The verification page JavaScript checks `window.location.hostname` against `qrauth.io`. If it does not match, the page shows a phishing warning.
:::

## Trust score coloring reference

```ts
function trustColor(score: number): string {
  if (score >= 80) return '#00a76f'; // green
  if (score >= 50) return '#ffab00'; // amber
  return '#ff5630';                  // red
}
```

The same color is used for:
- The shield fill during the color sweep.
- The trust badge background in the detail view.
- The border on the visual fingerprint frame.

## Mobile design

The reveal is designed for portrait mobile viewports (360px+):
- All animations use `transform` and `opacity` only (no layout-triggering properties).
- Font sizes use `clamp()` to scale between 360px and 768px.
- The shield SVG is `100px × 100px` on mobile, `140px × 140px` on desktop.
- Touch-to-dismiss collapses the reveal on small screens.
